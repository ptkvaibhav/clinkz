- **#51 — A measurement that reuses the object under test measures the test, not the deployment; and "correct" and "broken" both look like a zero.** Prompt caching shipped with a green suite and cost money for a week: the stability test handed the client the SAME `PromptSegments` object twice and asserted the two requests carried the same prefix, which is true of the mechanism and says nothing about the caller — production put the *engagement's growing endpoint inventory* in the cached span, presented on exactly ONE call per run, so across 154 traces there were 96,759 cache-WRITE tokens and **zero** reads, a flat 25% premium on that span. - **#55 — An LLM call that decides nothing still costs, and the cheap way to find out is to count what it CHANGED.** Five methodology checkpoints were asked a question their own deterministic classifier already answered; measured over the recorded traces they overrode it 0/227 (`csrf`), 0 (`weak_session`), 5/57 (`js_attacks`) and 3/296 (`brute_force`). So: measure the override RATE before defending a checkpoint; when a model writes a value into evidence, check that something constrains it to an observation that happened; assert the model is **not called** (`llm.prompts == []`), never that the verdicts match, since the latter passes against a version that asks and discards; and state the recall the removal costs as a pinned test rather than a hope. → [narrative](../docs/methodology/deterministic-verdict-classes.md)
- **#56 — A stamp can disclose reduced coverage; it cannot disclose an absence.** Routing v2 made any provider fallback a *disqualifying event* — stamped `provider_degraded` in client mode, fatal in baseline mode — and that is the right answer for a planning call and the wrong one for two kinds. Of the twelve Gemini-served exploit calls in the recorded traces, six were exploit plans and six were **false-positive cross-checks**: the suppression path. A degraded plan costs coverage and the stamp names it; a degraded cross-check DEMOTES a confirmed finding, and there is then no row to caveat, no section that names it, and nothing separating "the engine did not find it" from "a cheaper model decided it was not real". So classify by what the answer BECOMES (plan / emit / suppress), not by agent role — the exploit agent does all three through one client — refuse the fallback outright on emit and suppress in *both* run modes, and note that refusing is the conservative direction on both (the caller's existing unreachable-model handling leaves the finding standing and the methodology on its deterministic build). Enforce with a source scan that fails on an unclassified call site, since the permissive value is the default. → [narrative](../docs/provider-routing.md)
- **#57 — A benchmark profile is a control variable, and widening it changes the experiment, not just the safety margin.** Re-running the DVWA ladder to convert 21 stored `NO_ARM` rows into a measurement, the profile was written fresh with all nine permittable categories on the reasoning that a disposable container tolerates anything. The prior ladder had permitted exactly three (`data_reset`, `deletion`, `unsafe_method`) and said why in its own notes — "categories match the 2026-08-17 ladder exactly so the only variable between the two ladders is the engine". Permitting `credential_change` authorises DVWA's own `/vulnerabilities/captcha/` module, which IS a password-change flow (`step=1&Change=Change&password_new=…`), so the run changed admin's stored hash and the `admin_hash_unchanged` secondary gate failed — correctly, and not an engine defect: the rails asked and the profile said yes, logged as `category: mutating_method` in `actions.jsonl`. Two variables had moved at once (the new control-arm gate AND the destructive surface), so no difference in the survival table could be attributed to either. Measured cost of the widening: **zero extra findings** — 521 state-changing requests against the prior 310, for the identical 7 header + 15 exploitation counts at `low`. Read the prior bundle's `authorization.benchmark_profile` before writing a new one, change one variable per run, and treat a secondary gate that suddenly fails as a question about your own configuration before it is a question about the engine. → [narrative](../docs/lessons/README.md#lesson-57)
- **#58 — The instruction file is subject to its own laws, and the one bound nobody guarded was the one that degrades silently.** `CLAUDE.md` reached **152,205 characters against a ~150k load limit** — every other bound in this engine is loud (the plan cap logs its drops, the crawl budget renders a section, the governor refuses), and the file *containing those rules* was approaching a limit whose failure mode is a silent truncation with nothing in the transcript naming what was cut. The layout made it worse than the number: `## Key Design Decisions` was 92,680 characters, 61% of the file, which pushed `## Pre-Push Verification` and `## Important Rules (NEVER)` into the **last 3,120 characters** — so the first thing a cut would take is the gate discipline and the hard NEVERs, and the symptom would be an agent that quietly stopped running the gates. Verify before believing the premise: the file loaded **complete** this session (the closing paragraph and every heading arrived), so the report is "not yet truncated, and positioned so that the highest-value content is first to go", not "rules have been missing" — a guess in either direction would have been a claim nobody measured. Three durable pieces. **Split by kind, not by size**: CLAUDE.md keeps the RULE (one line, plus the code pointer), `docs/` keeps the INCIDENT — 85 invariants at ~1,090 chars each are 85 rules and 85 stories, and only the first is needed every session; 152,205 → 41,979. **Move verbatim, then prove it**: the relocation was done by script rather than retyped, and a sentence-level coverage check over the pre-split file showed 9 of 667 units absent, each an intentional rewrite — a split defended by "I was careful" is how a doc silently loses a rule. **Then guard it the way this codebase guards everything else**: the domain is COMPUTED (every tracked `CLAUDE.md`) so a new always-loaded file cannot escape it, only the tier classification is hand-maintained, an unclassified member FAILS rather than being skipped (the guard-domain law), the unit is decoded characters and not bytes (`wc -c` said 155,526 where the loader saw 152,205 — 2.2% in the direction that flatters the file), and the negative control is a test that watches it refuse the pre-split file. It is a CI job, not a step, because it must run on **doc-only PRs** — exactly the PRs that grow an instruction file, and exactly the ones CLAUDE.md permits to skip gates 1–2. → [`docs/invariants.md`](../docs/invariants.md), [`.claude/hooks/README.md`](hooks/README.md)
