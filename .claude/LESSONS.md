# Lessons (index)

A small, append-only archive so the same error is not made twice.

- **Consulted** during planning ONLY when a task resembles a past failure. Not
  read by default — do not open it for unrelated work.
- **Appended to** ONLY after an error worth not repeating.
- Each lesson has a **stable id** (`#14`–`#34`) cited elsewhere as `LESSONS #N`.
  Ids are historical — do NOT renumber (the sequence begins at #14; earlier ids
  are retired). Full narratives live in
  [`docs/lessons/README.md`](../docs/lessons/README.md); this file is the index
  (title + the rule each produced). Append a new lesson with the next id, add its
  narrative there, and add a one-line pointer here.

- **#24 — Piping the keyless gate through `tail`/`&&` reports the pipe's exit, not pytest's.** Capture pytest's own exit code directly (`… > out.txt 2>&1; echo "EXIT=$?"`). → [narrative](../docs/lessons/README.md#lesson-24)

- **#26 — Reusing a signature/matcher across a new response channel needs a content-shape check.** A line-anchored regex tuned for a raw channel fails on a wrapped/embedded one; reproduce the real wrapped response in a test. → [narrative](../docs/lessons/README.md#lesson-26)
- **#27 — Uniform confirm across a graded control = the oracle matches the benign response.** Treat uniform-confirm-at-every-security-level (incl. impossible) as a prime phantom signal; prove the wire reached the app; an acceptance marker must never be a substring the app emits on its benign/failure path. → [narrative](../docs/lessons/README.md#lesson-27)
- **#28 — A phase-2-confirmed primitive: phase-4 must prefer the deterministic build over the live LLM.** The LLM paraphrases/mangles a proven payload (a dead `%00`); back a stack-conditioned branch with a deterministic protocol artifact (PHPSESSID), never the flaky LLM tech list alone. → [narrative](../docs/lessons/README.md#lesson-28)
- **#29 — Confirms NOTHING in-pipeline but passes its isolated skill test = a DISPATCH gap.** Check the endpoint even REACHED the method with the params it needs (read the trace's per-endpoint phase events); pair an isolated `_test_*` test with a through-dispatch test; a first-seen dedup loses the richer duplicate. → [narrative](../docs/lessons/README.md#lesson-29)
- **#30 — A "FALSE POSITIVE" call can itself be a misdiagnosis.** Reconstruct the EXACT request the code issued (read the recorded `tool_invocations`/trace) before calling a full-pipeline finding a phantom; `_build_request_url` REPLACES same-named params (never doubles). → [narrative](../docs/lessons/README.md#lesson-30)
- **#31 — The live Log4Shell OOB channel is `jndi:dns://<collab>:<dns_port>/<nonce>`, not `ldap://`.** Empirically probe which callback fires from the live target's runtime before coding the OOB channel; `host.docker.internal` can resolve IPv6-first inside a container. → [narrative](../docs/lessons/README.md#lesson-31)
- **#32 — A driver's verdict logic can report a real PASS as INCOMPLETE.** Read where the methodology actually put the confirmation (`finding.evidence`), not an assumed attribute; read the raw finding output before trusting a verdict line. → [narrative](../docs/lessons/README.md#lesson-32)
- **#33 — Prove "X changes nothing emitted" with an A/B that holds structure constant.** Vary ONLY X, never diff two differently-structured runs; a "nothing reads Y" grep must match the READER symbol only (a write/recompute call is not a read). → [narrative](../docs/lessons/README.md#lesson-33)
- **#34 — A guard whose activation is per-clone local config does not exist.** `core.hooksPath` is never committed, so a fresh clone is inert and `--no-verify` skips what is configured — only a server-side (CI) check is bypass-proof; bootstrap the local layer in one command and make the setup command *report* whether it is active; and match a guard fail-CLOSED (tokenize, never pattern-match an open-ended option run). → [narrative](../docs/lessons/README.md#lesson-34)
- **#35 — The gate you ran is not the gate CI runs.** Clear the provider keys to reproduce the keyless gate locally (`load_dotenv()` makes it live otherwise); never give a test-support script a `test_` prefix (collection imports it in-process and an abort = zero tests run, not one failure); bound a dependency's major version to what you verified (`mcp[cli]>=1.0.0` resolved to a 2.0 that dropped `mcp.server.fastmcp` on CI only). → [narrative](../docs/lessons/README.md#lesson-35)
- **#36 — The FP detector can veto a deterministic oracle.** A post-run LLM demoted a *verified* boolean-blind SQLi because a 6-byte differential "seemed marginal" — 6 bytes WAS the signal; run the suppression side by the same rule as emission (a demotion must name a deterministic CONTRADICTION in the evidence, never a doubt), make a thin measurement self-evidencing (repeat baseline/true/false, require the delta identical in every repeat) rather than loosening the gate, and apply such a ground at the EMISSION chokepoint so honesty does not depend on whether an LLM noticed. → [narrative](../docs/lessons/README.md#lesson-36)
- **#37 — A zero-confirmation adaptation loop reads as coverage.** 110 rungs / 0 confirmations, 106 of them with the true and false bodies byte-identical (i.e. firing on parameters that reach no query): gate an adaptation loop on a *demonstrated capability signal* rather than on "our payloads all failed", log a deterministic CAUSE per attempt so the next zero-confirm run is diagnosable from the trace, and commit to deleting it if it still confirms nothing. → [narrative](../docs/lessons/README.md#lesson-37)
- **#38 — Accepted-by-the-store is not executed-by-the-server, and a path fragment is not evidence about a route.** Phase 2 learns which upload extensions were *accepted*; only the server's handler mapping decides which RUN (`.phtml` uploads fine under `<FilesMatch \.php$>` and is served inert), so walk the empirically confirmed set instead of trusting one LLM pick — a contract skill must not need a lucky guess. Likewise decide "source listing vs live handler" on what came BACK, never on the path: DVWA's `open_redirect/source/low.php` IS the live handler. → [narrative](../docs/lessons/README.md#lesson-38)
- **#39 — Whether the confirming attempt runs must never be the LLM's call.** A methodology whose *attempt* is gated on a model's opinion has the description as its only reachable outcome: the JS class asked the LLM `should_attempt_bypass` and its replay handled only string-literal writes, so on a real computed token (`md5(rot13(phrase))`) it never submitted anything and emitted the mechanism instead. Drive the attempt deterministically (whenever the primitive is replayable), make phase-N raise without the confirmation, and give the confirmation a control that differs from the payload in exactly one respect — same length AND character class, so a rejection cannot be about shape. → [narrative](../docs/lessons/README.md#lesson-39)
- **#40 — A class floor guarantees a class a task, not a task where the class can fire.** Three missed findings across four D1 runs (`weak_id` 1/3, `brute/` 1/3, `sqli/` 0/1) all came from one place: the plan cap drops ~480 of ~620 tasks, and the relevance grade "shape-compatible but unremarkable" is a huge tie bucket broken by *crawl order*, which varies per run. The endpoint that can actually confirm sat in that tie. Rank on a signal the scan already observed (a cookie actually set) rather than a path substring, and break ties on something stable — a coverage floor that ignores where the vuln lives is a coin flip wearing a guarantee. → [narrative](../docs/lessons/README.md#lesson-40)
- **#41 — A guard that parses text the target controls hands the target a vote.** The new "`likely` never confirms" gate read `strength=` out of the finding's evidence — but `_make_finding` puts the raw `Response:` bytes at index 1, *ahead* of the engine's own verdict line, so a host echoing `<!--strength=likely-->` beside its reflection would have deleted a genuine, deterministically-confirmed finding. Read a typed field, or restrict the parse to entries that are wholly `key=value` (a rendered dict or a `Response:` line then cannot qualify) — and remember an evidence entry is a list ELEMENT, so `startswith` is injection-resistant where a mid-string search is not. A suppression primitive handed to the host under test is worse than the phantom the guard prevents. → [narrative](../docs/lessons/README.md#lesson-41)
- **#42 — One inversion recurs across classes; fix it at the chokepoint AND at each source.** `strength="likely"` mapping to `status=confirmed` was fixed once at the DOM-XSS dispatch and was still live in three more classes (upload `client_side_only`, reflected XSS in JS/DOM context, the sqlmap fallback) because `_make_finding` stamps CONFIRMED unconditionally and each dispatch read only `verified`. Close a vocabulary in BOTH directions with a test that fails on any unclassified literal — a deny-list of "anything but `verified`" would have demoted `dom_redirect`, a genuinely witnessed effect. And parse the AST, not a grep: both live inversions were ternaries whose losing branch a grep for the assignment misses. → [narrative](../docs/lessons/README.md#lesson-42)
